# 식단기록 PWA (v2)

나 혼자 쓰는 식단기록 앱입니다. 달력에서 날짜를 누르고, 엑셀처럼 한 줄에 "제육볶음 200g"이라고 적으면 영양값이 자동으로 채워집니다.
기록은 기기의 IndexedDB에만 저장되고, 밖으로 나가는 것은 **영양 조회용 음식명뿐**입니다.

- 빌드 도구 없음: 순수 HTML/CSS/JavaScript(ES 모듈). 외부 라이브러리는 `vendor/chart.umd.min.js`(Chart.js 4.6.1, MIT) 하나만 파일로 포함
- 영양 조회: 기기 캐시 → Cloudflare Workers 프록시 → 식약처 식품영양성분DB → (없으면) Claude API 추정
- GitHub Pages에 정적 파일로 배포, 홈 화면에 설치해 오프라인에서도 사용

## 파일 구성

```
index.html              하단 탭(캘린더|통계|내 정보) + 일별 상세 레이어
style.css
config.js               PROXY_URL 설정 (배포 후 여기만 수정)
manifest.webmanifest
sw.js                   서비스 워커 (앱 셸 캐시 우선, 프록시 요청은 네트워크)
vendor/chart.umd.min.js Chart.js
js/app.js               진입점: 탭·뒤로 가기·초기화·online 재조회
js/db.js                저장소 선택 (Claude 아티팩트면 계정 저장소, 아니면 기기 저장소)
js/db-idb.js            기기 저장소: IndexedDB v2 스키마, v1→v2 마이그레이션
js/db-cloud.js          Claude 계정 저장소 (claude.ai 아티팩트로 열었을 때)
js/util.js              날짜·숫자·끼니 기본값·DOM 헬퍼
js/calendar.js          월간 캘린더
js/parse.js             "제육볶음 200g" → 음식명/양 분리
js/day-table.js         일별 엑셀식 입력 표 (즉시 저장, Enter/Tab, 스와이프 삭제, 자동완성)
js/lookup.js            영양 조회 큐 (캐시 → 프록시), 후보 칩, 직접 수정
js/day-charts.js        일별 그래프 2개 (칼로리 게이지, 끼니별 막대)
js/profile.js           내 정보: BMI, 권장 칼로리(자동/직접 입력), 체중 기록
js/stats.js             통계 탭
worker/worker.js        Cloudflare Workers 프록시
worker/wrangler.toml    프록시 배포 설정
tools/import_foods.py   (선택) 공공 CSV → foods.json, 기기 캐시 미리 채우기
icons/
```

## 1. 로컬에서 실행

```bash
cd diet-pwa
python -m http.server 8000
```

`http://localhost:8000` 을 엽니다. `config.js`의 `PROXY_URL`이 비어 있으면 기기 캐시에 있는 음식만 채워지고, 나머지 줄은 "못 찾음(?)"으로 남습니다. 그럴 때는 숫자 칸을 길게 눌러 직접 넣을 수 있습니다.

## 2. 프록시 배포 (Cloudflare Workers)

### 2-1. 키 준비

1. **공공데이터포털 인증키**: [data.go.kr](https://www.data.go.kr)에서 "식품의약품안전처_식품영양성분DB정보"를 활용신청합니다. 개발계정은 자동 승인되며 하루 10,000건까지 쓸 수 있습니다. 마이페이지의 **일반 인증키(Decoding)** 값을 씁니다.
2. **Anthropic API 키**: [console.anthropic.com](https://console.anthropic.com)에서 발급합니다. 공공 DB에 없는 음식의 추정에만 쓰이며, 기본 모델은 `claude-haiku-5-5`입니다. 이 키가 없으면 추정 단계는 건너뛰고 "못 찾음"으로 처리됩니다.

### 2-2. 배포

```bash
npm i -g wrangler
wrangler login
cd worker
# wrangler.toml의 ALLOWED_ORIGINS를 내 주소로 수정: "https://<아이디>.github.io,http://localhost:8000"
wrangler secret put DATA_GO_KR_KEY
wrangler secret put LLM_API_KEY
wrangler deploy
```

배포가 끝나면 `https://diet-proxy.<계정>.workers.dev` 같은 주소가 나옵니다. 이 주소를 앱의 `config.js`에 넣습니다.

```js
export const PROXY_URL = 'https://diet-proxy.<계정>.workers.dev';
```

### 2-3. 프록시 동작

- `GET /nutrition?q=음식명` → `{ status: 'found'|'estimated'|'not_found', candidates: [...] }`
- **CORS:** `ALLOWED_ORIGINS`에 적은 주소만 허용합니다. Origin이 없거나 다른 요청(curl 등)은 403입니다.
- **검색어 변형:** 원래 이름으로 공공 DB에서 못 찾으면 최대 4번까지 바꿔 다시 검색합니다. 크기 표기(15cm, 6인치, 라지, 톨 등)를 떼고, 앞에 붙은 브랜드명(서브웨이, 맥도날드, 스타벅스, CU 등)을 떼고, 흔한 영문 메뉴명을 한글로 바꿉니다(BLT → 비엘티, BMT → 비엠티). 예를 들어 `서브웨이 BLT 15cm`는 `서브웨이 BLT` → `BLT` → `비엘티` 순으로 검색합니다. 이때 업체명에 그 브랜드가 들어 있는 결과를 먼저 보여 줍니다. 브랜드·약어 목록은 `worker.js`의 `BRANDS`, `EN_KO`에서 추가할 수 있습니다.
- **웹 검색 후 AI:** 공공 DB에서 끝내 못 찾으면 Claude가 **웹 검색**(Anthropic 웹 검색 도구, 최대 3회)으로 브랜드 공식 영양성분표 같은 자료를 찾아 값을 만듭니다. 원래 이름을 그대로 넘겨 그 브랜드의 해당 메뉴·크기 기준으로 찾게 하고, 1회 제공량도 그 크기 1개의 중량으로 받습니다(예: 서브웨이 15cm 1개의 g). 찾은 페이지 주소는 `source_ref`에 `web:주소`로 저장되고, 줄의 노란 ≈를 누르면 어느 사이트 값인지 보여 줍니다.
  - 웹 검색이 꺼져 있거나 실패하면 검색 없이 추정합니다. 웹 검색은 콘솔에서 조직 관리자가 끌 수 있고, 검색당 요금이 따로 붙습니다. 끄려면 `LLM_WEB_SEARCH = "0"`으로 설정합니다.
  - 미리보기(claude.ai 아티팩트)로 열었을 때는 프록시가 없어도 화면에서 바로 Claude에게 추정을 요청합니다(검색 없음, 처음 한 번 허용 요청). GitHub Pages에서는 이 기능이 동작하지 않고 프록시를 씁니다.
- **캐시:** 같은 음식명 결과는 Workers 캐시에 보관해서 외부 API 호출을 줄입니다(찾음·추정 30일, 못 찾음 1일).
- **조회 수 제한:** IP당 하루 `DAILY_LIMIT`(기본 300)회입니다. KV를 연결하지 않으면 인스턴스별로 대략만 셉니다. 정확하게 세려면 `wrangler.toml` 주석의 KV 설정을 쓰세요.
- **식약처 응답 매핑:** API는 `FoodNtrCpntDbInfo02/getFoodNtrCpntDbInq02`이고, 필드는 `FOOD_NM_KR`(식품명), `AMT_NUM1`(에너지), `AMT_NUM3`(단백질), `AMT_NUM4`(지방), `AMT_NUM6`(탄수화물), `NUTRI_AMOUNT_SERVING`(기준량), `SERVING_SIZE`/`Z10500`(1회 섭취참고량/식품중량)으로 매핑했습니다.
  **처음 배포한 뒤 한 번 확인하세요.** 활용신청 페이지의 참고문서 "출력메세지" 엑셀과 비교하거나, 브라우저에서 `https://<프록시>/nutrition?q=사과`를 열어 값이 상식적인지 봅니다(Origin 검사 때문에 앱에서 확인하는 게 편합니다). 번호가 다르면 `worker.js` 맨 위의 `F` 객체만 고치면 됩니다.

### 2-4. config.js 설정

| 항목 | 설명 |
|---|---|
| `PROXY_URL` | 프록시 주소. 비우면 기기 캐시만 사용 |
| `SEED_FOODS_JSON` | `foods.json`으로 캐시를 미리 채울 때 `true` (기본 `false`) |
| `CHART_JS_URL` | Chart.js 위치. 그래프 화면을 처음 열 때만 불러와서 첫 화면이 빨리 뜹니다 |

## 3. GitHub Pages 배포

1. GitHub에 저장소를 만들고 이 폴더의 파일을 루트에 올립니다. `worker/`, `tools/` 폴더는 같이 올려도 되고 빼도 됩니다.
2. **Settings → Pages**에서 Branch를 `main` / `/ (root)`로 지정합니다.
3. `https://<아이디>.github.io/<저장소>/` 로 접속합니다.
   CORS 허용 주소에는 경로를 뺀 `https://<아이디>.github.io`만 적습니다.
4. Android Chrome에서 메뉴 → **홈 화면에 추가**를 누르면 설치됩니다.

**업데이트할 때:** 서비스 워커가 캐시 우선이라, 파일을 바꾸면 `sw.js`의 `CACHE_VERSION`을 올려야 합니다(현재 `v10`). 새 버전은 앱을 연 다음 번 실행부터 보입니다.

## 4. 사용법

### 캘린더 (메인)

- 날짜 칸마다 그날 섭취 kcal과 색 점이 표시됩니다. 권장 칼로리 대비 90–110%는 초록, 110% 초과는 빨강, 90% 미만은 노랑입니다.
- 오늘은 초록 배경과 두꺼운 테두리, 선택한 날은 얇은 테두리로 표시됩니다.
- 날짜를 누르면 일별 상세로 들어가고, Android 뒤로 가기를 누르면 캘린더로 돌아옵니다.

### 일별 상세: 입력 표

**입력**
- 표는 **아침·점심·저녁** 구역으로 나뉘고, 구역마다 빈 줄이 하나씩 있습니다. 빈 줄에 적으면 그 끼니로 저장되고, 구역 아래에 새 빈 줄이 생깁니다. 간식은 맨 아래 "+ 간식 추가"로 열고, 간식 기록이 있는 날은 처음부터 보입니다.
- 빈 줄에 바로 적습니다. **Enter**는 다음 줄, **Tab**은 다음 칸으로 이동합니다. 칸을 고치면 바로 저장됩니다.
- 줄은 먼저 저장되고 영양 조회는 뒤에서 진행되므로, 기다리지 않고 다음 줄을 계속 적을 수 있습니다.

**양 표기**

| 입력 | 해석 |
|---|---|
| `제육볶음 200g`, `닭가슴살 0.2kg`, `콜라 250ml` | g (ml는 g과 같게 계산) |
| `라면 2`, `삼겹살 1.5인분`, `밥 한 공기` | 인분 (숫자만 쓰면 인분) |
| `바나나 1개`, `방울토마토 6개`, `피자 2조각` | 개 (1개 무게를 Claude에게 물어 저장. 모르면 1회 제공량으로 대략 계산) |
| `김밥 반`, `김밥 1/2` / `김밥 반개` | 0.5인분 / 0.5개 |
| `김밥` | 1인분 |

1회 제공량 정보가 없는 음식을 인분이나 개로 적으면 1인분을 100g으로 계산하고, 양 칸에 노란 ≈ 표시가 붙습니다. g으로 적으면 정확해집니다.

**끼니**
- 줄은 입력한 구역의 끼니로 저장됩니다. 다른 끼니로 옮기려면 지우고 그 구역에 다시 적어 주세요.

**줄 상태 아이콘**

| 아이콘 | 뜻 |
|---|---|
| 스피너 | 조회 중 |
| ✓ | 확인됨 (공공 DB 또는 직접 수정한 값) |
| ≈ (노랑) | AI 추정값 |
| ? (빨강) | 못 찾음. 누르면 이름을 고쳐 다시 조회 |
| ↻ | 오프라인. 연결되면 자동으로 다시 조회 |

**후보·수정·삭제**
- **후보 칩:** 후보가 여러 개면 줄 아래에 최대 3개가 뜹니다. 첫 번째가 기본으로 선택되고, 다른 칩을 누르면 바꿀 수 있습니다.
- **값 수정:** kcal 칸을 **길게 누르면** 직접 고칠 수 있습니다. 고친 값은 그 음식의 캐시에도 저장되어 다음 기록부터 적용됩니다.
- **줄 삭제:** 줄 오른쪽 끝의 × 버튼을 누르거나, 왼쪽으로 밀거나, 음식 칸을 비우고 Enter를 누릅니다. 삭제 직후 토스트의 "되돌리기"로 복구할 수 있습니다.
- **자동완성:** 음식 칸에 타이핑하면 이전에 기록한 이름이 빈도순으로 최대 5개 뜹니다.

### 내 정보

- **입력 항목:** 키, 몸무게, 나이, 성별, 활동량, 목표를 넣으면 BMI(대한비만학회 기준 분류), 기초대사량(Mifflin-St Jeor), 권장 칼로리를 계산합니다. 권장 칼로리는 10 단위로 반올림하고, 목표에 따라 감량 −500, 증량 +300을 보정합니다.
- **몸무게:** 몸무게 칸에 입력하면 오늘 체중 기록으로도 저장됩니다. 몸무게는 항상 가장 최근 체중 기록으로 자동 반영됩니다.
- **권장 칼로리 설정 방식:** "자동 계산"이면 위 정보와 최신 체중으로 계산하고, "직접 입력"이면 입력한 값으로 고정합니다(체중이 바뀌어도 그대로).
- 표와 그래프에는 칼로리만 표시합니다. 탄수화물·단백질·지방 값은 조회 결과와 함께 저장만 해 둡니다.

### 통계

- **주/월 전환:** 주 단위는 월요일부터 일요일까지입니다.
- **그래프:**
  - 일별 kcal 막대와 권장 기준선
  - 자주 먹은 음식 TOP 10
  - 권장 범위(90–110%) 안에 든 날 수
  - 체중 추이

## 5. 기기 캐시 미리 채우기 (선택)

공공데이터포털의 "전국통합식품영양성분정보(음식)" CSV를 `foods.json`으로 바꿔 앱 폴더에 두고 `config.js`의 `SEED_FOODS_JSON`을 `true`로 바꾸면, 앱이 처음 실행될 때 캐시에 넣습니다. 이렇게 하면 자주 먹는 음식은 프록시 없이, 오프라인에서도 바로 채워집니다.

```bash
python tools/import_foods.py 음식DB.csv -o foods.json
python tools/import_foods.py 음식DB.csv --list-columns   # 컬럼 확인
```

- 인코딩은 utf-8-sig로 먼저 읽고, 실패하면 cp949로 읽습니다.
- 컬럼은 자동으로 찾고, `--name-col`, `--kcal-col` 등으로 직접 지정할 수도 있습니다.
- 기준량이 100g이 아니면 100g 기준으로 환산하고, 같은 이름은 처음 나온 것만 남깁니다. CSV 여러 개를 합칠 수 있습니다.
- `foods.json`의 version이 바뀌면 새 음식만 추가합니다. 이미 캐시에 있는 음식, 특히 직접 고친 값은 덮어쓰지 않습니다.
- 배포할 때 `sw.js`의 `CACHE_VERSION`도 올리세요.

## 6. 기록이 저장되는 곳

| 여는 방법 | 저장 위치 | 특징 |
|---|---|---|
| GitHub Pages, 로컬 서버 | 이 기기의 IndexedDB | 오프라인·홈 화면 설치 가능. 기기·브라우저마다 따로이고, 사이트 데이터를 지우면 사라짐 |
| claude.ai 아티팩트 링크 | 본인 Claude 계정의 개인 저장 영역 | 같은 계정이면 PC·폰 어디서나 같은 기록. 본인만 읽고 씀. 오프라인·설치 불가 |

- **계정 저장 방식:** 계정 저장소는 하루치 기록을 문서 1개로, 음식 캐시는 음식마다 문서 1개로 저장합니다. 앱을 열 때 전부 읽어 오고, 바꾸면 0.4초 안에 모아서 저장합니다.
- **기기 간 반영:** 다른 기기에서 바꾼 내용은 앱을 다시 열거나, 다른 앱에 갔다가 30초 이상 지나 돌아오면 반영됩니다.
- **기존 기록 옮기기:** 계정 저장소가 비어 있을 때 같은 브라우저에 예전 기록이 있으면 한 번 자동으로 옮겨 옵니다.

## 7. 데이터 구조 (IndexedDB `diet-log` v2)

| 스토어 | 키 | 인덱스 | 내용 |
|---|---|---|---|
| `foods` | `id` | `name_key`(unique) | 영양값 캐시 (100g 기준, `source`: public_api / ai_estimate / manual) |
| `meal_logs` | `id` | `date`, `lookup_status` | 표의 한 줄 (아래 참고) |
| `profile` | `'me'` | — | 키·몸무게·나이·성별·활동량·목표·권장 칼로리·고정 여부·탄단지 비율 |
| `weight_logs` | `id` | `date`(unique) | 날짜별 체중 |
| `settings` | `key` | — | seed_version 등 |

**`meal_logs` 필드**
- **기본:** `date`, `row_order`, `meal_type`, `raw_text`, `food_name`, `created_at`, `updated_at`
- **양:** `amount_qty`, `amount_unit`(serving / g / piece), `amount_g`
- **영양:** `food_id`, `kcal`, `carb`, `protein`, `fat` (조회 전에는 null)
- **조회 상태:** `lookup_status`(pending / found / estimated / not_found / offline)
- **보조:** `candidates`(후보 칩), `candidate_index`, `approx`(100g 가정 여부)

**규칙과 이전 버전**
- **합계:** 저장된 원값을 더하고 표시할 때만 반올림합니다. 값이 없는 줄(조회 중·못 찾음)은 합계에서 빼고 "(값 없는 n줄 제외)"로 표시합니다.
- **v1에서 업그레이드:** 기존 기록은 그대로 옮겨지고(상태 found), 직접 등록한 음식은 manual 캐시로 남습니다. v1의 샘플 음식은 삭제됩니다.

## 8. 알아 둘 점

- **AI 추정값은 대략치입니다.** 노란 ≈ 표시가 있는 값은 길게 눌러 고치면 이후 계속 그 값이 쓰입니다.
- **오프라인 조회:** 오프라인에서도 입력·수정·삭제는 모두 됩니다. 처음 보는 음식은 연결된 뒤 자동으로 조회됩니다.
- **권장 칼로리:** BMI와 권장 칼로리는 참고용 계산치이며 의료적 판단이 아닙니다.
- **데이터 보관:** 데이터는 이 기기의 브라우저 저장소에만 있습니다. 사이트 데이터를 지우거나 앱을 삭제하면 함께 지워집니다.
